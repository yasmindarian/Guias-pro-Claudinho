Start every AI chat knowing where you left off

A three-file setup that lets Claude pick up a project in seconds, read only what the task needs, and keep each chat cheap. It comes from how we documented NorthStar, and it works for any project.

The problem

Claude does not remember earlier chats. Whatever it needs to know, it has to read again at the start of each new one. If the whole project lives in one big document, every chat begins by reading all of it, and every message after that carries it along. That is slow, it eats your usage limits, and it buries the three things that matter today under months of history.

The fix is to split the project's memory by how often it is needed: a small file read every time, a big file read only in slices, and a third file for history that is almost never opened.

The three files

Claude picks a short prefix from your project name for the file names, so you never type one (NorthStar's files start with PX). There is an optional fourth piece: a readable summary for people who do not use the AI. Claude updates it only when someone asks.

Set it up once

About 30 minutes. You paste, Claude does the writing.

  1. Make a folder.Create a folder for the project on your computer, for example Documents/MyProject. The files are Markdown (.md), which is plain text with simple formatting. Any text editor opens them.
  2. Create a Project in Claude.Give it a name. Leave the instructions empty for now, because Claude writes them for you in step 4.
  3. Paste the setup prompt.Open a chat inside the Project and paste Prompt 1. Claude asks one round of questions, then writes the three files. If you already have notes, documents or old chats about the project, use Prompt 5 instead.
  4. Save the files in the right places.Put the core in the Project's Knowledge. Put the reference and archive in your project folder only. Then paste the instructions block Claude gave you into the Project settings.
  5. Test it.Start a fresh chat in the Project and paste Prompt 6 (token check). It should list the core file and the instructions, and nothing else big. If the reference shows up, move it out of Project Knowledge.
  6. Work.Begin each chat with Prompt 2 and end it with Prompt 3.

Why the reference stays out of Project Knowledge. Files attached to a Project are available to every chat in it, and depending on size and plan they can be loaded in full each time. That is the exact cost we are removing. If the reference sits there, you may pay for it on every chat even though the instructions say not to read it.

Which tool are you using? In Claude Cowork (or any setup where Claude can open files in a folder), Claude reads one section of the reference by itself. That is the best case. In a plain chat with no folder access, Claude cannot open the reference on its own. Tell Prompt 1 so in the interview, and it will split the reference into four to six small topic files and tell you which one to attach for which task.

Every working session

Start

New chat. Paste Prompt 2 with today's goal.

Claude reads the core and answers in five lines: where you stopped, what it suggests, what it cannot confirm.

Work

One chat per task. Ask for sections by name, never for "all the files".

If the chat gets long or Claude starts repeating itself, close it.

Close

Paste Prompt 3.

Claude updates only the sections that changed, rewrites "Where we stopped", bumps the version and hands you the new files. Save them over the old ones.

Habits that keep it cheap

  • One chat per task. Long chats re-send everything on every message.
  • Say your goal in the first message. Claude then knows what to read.
  • Close the session before the chat gets long, not after it breaks.
  • Keep the core under 30 KB. When it grows, run Prompt 4.
  • Update the stakeholder summary only when someone needs it.
  • Turn off connected apps the project does not use. Each one adds tools Claude carries into every chat.
  • Never delete history. Move it to the archive, word for word.

When something looks wrong

What you seeLikely causeFix
Claude reads the whole reference at the start.The reference is in Project Knowledge, or the instructions block is missing.Move the reference to the folder. Re-paste the instructions. Run Prompt 6 to confirm.
Claude does not know what happened last time.The close step was skipped, or the new core was not saved over the old one.Compare the version number at the top of the core with the one Claude quotes back.
Claude says it cannot open the reference.No folder access in this tool.Use topic files (see the callout in the setup).
Two copies of a file disagree.Drift. One copy was updated and the other was not.Check the version line in both. Keep the newer one and overwrite the other.
The core keeps growing.History is piling up in a file read every time.Run Prompt 4 and approve what moves to the archive.
A guess shows up in the files as a fact.The labels were not used.Ask Claude to relabel the section. The label rules live in the core file.

Archive file

  
Resolved items, old changelog entries, past meeting detail. Text arrives word for word under the heading of the section it came from, with the version it left in. Where it used to be, a one-line italic pointer remains: "Archived on 14/10 (v1.4): what left, and where the live information is."

  
Never moves to the archive: open questions, open risks, active rules, the current state, and decisions (replaced decisions stay as struck-through lines).


  
Labels

  
Put one in front of any claim that is not obvious. They stop guesses from turning into facts.

  

    
LabelMeaning

    
      
[VERIFIED 14/10]Checked directly by looking at the real thing, on that date.

      
[DECIDED Ana]A named person decided it.

      
[PROPOSED]An idea from the AI that nobody confirmed.

      
[UNVERIFIED]Nobody checked it.

      
[PLACEHOLDER]Invented content that is not real data.

      
[CONFLICT]Two sources disagree. Both are kept until a person picks.

Archive
The third file. It holds history that no longer drives decisions: resolved questions, old changelog entries, detail from past meetings.In this system: text moves there word for word, a one-line pointer stays behind, and Claude opens it only when context is missing.

    
Changelog
A short list, newest first, of what changed in the documents: date, version, three to six lines.

    
Chat (or session)
One conversation with Claude. Claude does not remember other chats, so what it needs has to come from the files.In this system: a session is one chat plus its close step.

    
Close the session
The last step of a working chat. Claude updates the files with what happened, raises the version number and gives you the new files.Prompt 3.

    
Connector
A link between Claude and another app, such as Slack, Gmail or a project tracker.Each connected app adds tools Claude carries into every chat, so unused ones have a cost. Turn them off per project.

    
Context window
Everything Claude can see at one time: instructions, files, the chat so far and its own answers. It has a size limit.Think of it as the desk. Tokens are the papers on it.

    
Core file
The first file, under 30 KB, read in full at the start of every chat.It says where you stopped, what to do next, how you work, and where to find everything else.

    
Cowork
Anthropic's desktop app where Claude works with files in a folder on your computer.With it, Claude can open the reference file and read a single section.

    
Decision (D-01)
A numbered entry in the reference file for something a person decided, with who and when. Numbers are never reused.

    
Drift
When two copies of a document stop matching, for example the file in Project Knowledge is older than the one in your folder.The version number at the top of each file is how you spot it.

    
grep
A command that searches a file for a word and prints the matching lines. With the -n option it also prints line numbers.Claude uses it to list the headings of the reference file.

    
Handoff
A note written so the next chat, or the next person, can continue the work.In this system the handoff is the "Where we stopped" section, so there is no separate handoff file.

    
Hallucination
When Claude states something that sounds right but is not backed by anything.Labels like [UNVERIFIED] and [PROPOSED] keep such statements from becoming "facts" in the files.

    
KB (kilobyte)
A measure of file size. 1 KB is about 1,000 characters, roughly 250 tokens.A 30 KB core is about 7,500 tokens.

    
Label
A tag in square brackets in front of a claim that says where it came from, such as [VERIFIED 14/10] or [PROPOSED].See the Templates tab.

    
Lessons
A list in the core file of mistakes Claude made, one line each with the fix, so the next chat does not repeat them.

    
Markdown (.md)
A plain text file with light formatting marks: # for headings, - for bullets, | for tables. Any text editor opens it, and Claude reads it efficiently.

    
Open question (Q-01)
A numbered entry for something not yet decided. When answered it becomes a decision, and the question stays as a struck-through line.

    
Placeholder
A blank you fill in before sending a prompt.In this guide they are written in {curly braces} and highlighted.

    
Project (in Claude)
A workspace that groups chats with shared instructions and files.

    
Project instructions
Text you write once in the Project settings. It is loaded in every chat of the Project, so keep it short.Prompt 0.

    
Project Knowledge
The files attached to a Project. Depending on their size and your plan, they are loaded in full into each chat or searched when needed.Assume loaded in full: put only the core there.

    
Prompt
The message you send to Claude. In this guide, text you copy and paste.

    
RAG (retrieval)
When a Project has many files, the tool may search them and pull in only the matching pieces instead of loading everything.Useful, but you do not control it, so the setup does not depend on it.

    
Reference file
The second file, the large one. Everything that is not needed at the start of every chat.Read one numbered section at a time, never in full.

    
Routing table
The "Where to find what" table in the core file. It says which reference section holds which topic, and gives the command to read just that section.

    
Script
A short program Claude writes and runs for a mechanical job, such as copying text word for word or checking that no line was lost.Better than retyping, because a script does not make typos.

    
sed
A command that prints part of a file. With sed -n and two patterns it prints from one heading to the next.This is how Claude reads one section of the reference without opening the whole file.

    
Section number
Reference sections keep their numbers forever, because other text points to them (for example "see 5.9").

    
Skill
A packaged set of instructions Claude loads for one kind of task, such as making a Word file. The list of available skills is part of what Claude carries, like connectors.

    
Source of truth
The one place where the current, agreed version of something lives. If two documents disagree, it wins.

    
Stakeholder summary
An optional readable page for people who do not use the AI. Claude updates it only when asked, because rewriting a long page every session is expensive.Prompt 7.

    
Terminal
A text window where commands are typed. You will rarely open one. In Cowork, Claude runs commands for you.

    
Token
The unit Claude counts text in. Roughly 4 characters of English, a little fewer in other languages. Everything Claude reads and writes is measured in tokens, and both speed and usage limits depend on it.

    
Usage limits
How much you can use Claude in a given period. Bigger loads and longer chats use it up faster.

    
Verbatim
Word for word, unchanged.When text moves to the archive it is copied verbatim, by script, so nothing is rewritten by accident.

    
Version number
A number and a date at the top of each file (for example v1.4, 14/10). It goes up on every close. Quote it in a chat to check that Claude has the latest copy.
